# План 2 «React» — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Первая frontend-реализация AgroTrace на React 18 + TypeScript: все экраны ТЗ §9.4–9.6 на дизайн-системе «Поле», работающие с любым backend через шлюз, и общий набор e2e-тестов `tests/e2e`, который затем проверит Angular и Svelte.

**Architecture:** `frontend-react/` — Vite SPA. Данные — `@agrotrace/api-client` + TanStack Query; формы — React Hook Form + `@agrotrace/validation`; тексты — `@agrotrace/i18n`; бизнес-правила на клиенте (живой баланс масс, доступные действия) — `@agrotrace/domain`; стили и разметка — только `@agrotrace/design-system` (классы `at-*`, спрайт, иллюстрации; компоненты React повторяют README-контракты разметки дословно). Граф — Cytoscape.js, графики — ECharts, карты — Яндекс.Карты 3.0 (при отсутствии ключа — таблица). Публичная QR-страница — отдельный лёгкий entry (≤ 60 КБ JS gzip). Разработка и компонентные тесты не зависят от готовности backend: MSW-моки строятся из примеров контракта; e2e (`tests/e2e`, Playwright) гоняется против шлюза `react-express.localhost` на seed-данных.

**Tech Stack:** React 18, TypeScript strict, Vite 5, React Router 6, TanStack Query 5, React Hook Form 7 + @hookform/resolvers (zod), cytoscape + cytoscape-dagre, echarts, Vitest + @testing-library/react + MSW 2, Playwright + @axe-core/playwright.

**Spec:** `docs/tz-agrotrace-v2.md` §9 (экраны, маршруты §9.4 — дословно), §10 (дизайн-система и правила подачи текста), §4 (роли и видимость в UI). **Contract:** `contracts/openapi.yaml`. **Design system:** `packages/design-system/README.md` (разметка компонентов — обязательна). **Rulings:** `docs/superpowers/rulings.md`.

## Global Constraints

- Пользователь: без неона, без лишнего текста (заголовок экрана — существительное; без подзаголовков-пояснений; пустое состояние — иллюстрация + одна строка + одна кнопка; ошибки — что нарушено и что сделать), оригинальная дизайн-система «Поле», UI-библиотеки запрещены.
- Разметка каждого компонента — ровно по README дизайн-системы (классы, ARIA, состояния, клавиатура), чтобы Angular и Svelte дали идентичный DOM; компоненты React — тонкие обёртки.
- Маршруты — ровно §9.4 (включая query `?tab=`), состояние фильтров таблиц — в query-параметрах URL.
- Адаптивность от 360 px (сайдбар ≥1024, свёрнутый 768–1023, нижняя панель <768; таблицы → карточки; мастер переработки по шагу; граф и карта на весь экран).
- Доступность WCAG AA, работа с клавиатуры, видимый фокус, `aria-live` для тостов и ошибок.
- Тексты — только из `@agrotrace/i18n` (ключи); даты `ДД.ММ.ГГГГ` через `formatRuDate`/маски R70; массы через `formatMass`; ошибки API — `problemMessage`.
- Файлы и изображения — подписанные/публичные URL из API (R28/R39), `withVariant` для 96/480; подпись авторов фото продуктов на публичной странице (R76 note).
- CSP шлюза: без inline-скриптов и стилей в `<script>`; Vite `server.fs.allow` на корень репозитория (domain импортирует JSON контрактов).
- Никаких обращений к API в обход `@agrotrace/api-client`; SSE через `openEventStream`.
- Коммиты — Conventional Commits, трейлер `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.

## Review Focus

1. **Идентичность DOM с README дизайн-системы** — сравнение снимков DOM ключевых компонентов (кнопка, поле, таблица/карточки, диалог, степпер) с эталонной разметкой README; расхождения сломают эквивалентность с Angular/Svelte.
2. **Права в интерфейсе** — пункты меню, кнопки действий и маршруты по ролям (§9.5) совпадают с x-roles контракта; прямой переход на чужой маршрут → `/403`; действия берутся из `actions` партии, а не вычисляются заново.
3. **Ошибки сервера на формах** — 400 `errors` раскладываются по полям (включая `items[1].batchId`), 422 правило + params показывается текстом правила, 409 VERSION_CONFLICT — перечитать и предложить повтор; ни одной «сырой» ошибки.
4. **Сессия** — вход, 2FA, истечение access-токена во время работы, несколько вкладок (Web Locks), выход во всех вкладках, SSE-переподключение.
5. **Мобильная ширина 360 px** — нет горизонтальной прокрутки на каждом маршруте, touch-цели ≥ 44 px, нижняя навигация.
